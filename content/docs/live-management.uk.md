Кожна дія з життєвим циклом акаунта та конфігурацією доступна без
редагування файлу конфігурації демона вручну чи його перезапуску - через
CLI або термінальний інтерфейс над тими самими даними.

## `signal2sip-gendb` - CLI

Супутній бінарник, окремий від демона, для всього, що стосується
акаунтів:

```
signal2sip-gendb <name> register --e164 <e164> sms   # новий акаунт, підтвердження SMS
signal2sip-gendb <name> link                          # зв'язати як вторинний пристрій (QR-код)
signal2sip-gendb <name> config get|set|list            # читати/писати SIP та конфігурацію розгортання
signal2sip-gendb <name> enable|disable                 # увімкнути/вимкнути, нічого не видаляючи
```

Все це працює напряму з базою даних демона - `gendb` не потребує
запущеного демона для реєстрації чи налаштування акаунта.

## `signal2sip-tui` - термінальний інтерфейс

Той самий список акаунтів, деталі/статус кожного та редактор
конфігурації SIP, що й у CLI, але в інтерактивному вигляді: список
акаунтів → деталі → редактор конфігурації, з вбудованою валідацією
(наприклад, транспорт TLS вимагає або закріплений CA-сертифікат, або
явну відмову від перевірки перед збереженням) і підтвердженнями
перед будь-якою деструктивною дією.

## Зміни застосовуються наживо

Коли демон уже запущений, він підхоплює зміни конфігурації двома
способами, залежно від того, що спрацює першим:

- **Негайно** через сигнал, який `gendb`/TUI надсилає одразу після
  зміни.
- **У межах короткого інтервалу опитування** у будь-якому разі, як
  запасний варіант - тож навіть зміна, зроблена коли демону не вдалося
  надіслати сигнал напряму, все одно застосується невдовзі після цього.

Перебудовується лише той акаунт, який справді змінився (його
SIP-реєстрація відновлюється, конфігурація перезавантажується) - усі
інші акаунти з активними дзвінками та реєстрацією залишаються
недоторканими.
